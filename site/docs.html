    Documentation

    Everything reef does, in the order you are likely to need it: what it is, how memory is organised, how your assistant reads and writes it, and how to connect one.

    What reef is

    reef is a shared, living memory for a group of people and the AI assistants they talk to. You keep engrams; your assistant reads them before it answers, and writes back to them as things change.

    Three things separate it from the memory built into an assistant:

    • Shared, not personal. A space belongs to a household, a project or a team, so everyone's assistant starts from the same picture.
    • A wiki, not a blob. Memory is engrams you can read, correct and reorganise — not an opaque store you have to trust.
    • Map before memory. An assistant loads an index of what exists, then fetches only the engrams the conversation actually needs.

    There are three ways in, all reaching the same memory:

    Way inAddress
    The browser app — read, edit, invite, exportreefwith.me/app
    Any assistant that speaks MCPhttps://reefwith.me/mcp
    The terminaluv tool install reef-cli

    reef is invitation-only. There is no public sign-up: you get in because someone already inside adds you to a space.

    Spaces and engrams

    A space is a small group and the memory it shares. You get one private space, called personal, the first time you sign in. You can create any number of shared ones — a household, a school circle, an accountant, a small project.

    Private spaceShared space
    Who can read itOnly youEveryone invited
    CreatedAt first sign-inBy whoever needs it
    NamedAlways personalBy you, for you
    People joinNeverBy email invitation from the owner

    You name a shared space for yourself. Your name for a space is yours alone. Two households can each have a family without either knowing the other exists, and nobody can take a name from anybody else. The consequence worth remembering: when someone tells you an engram is "in the family space", they mean their name for it, which need not be yours.

    An engram is Markdown, from the moment you write it. Each one carries a path such as plans.md, a title, tags, and a one-line description. The description is what an assistant sees in the index, so it is worth writing as a real summary rather than a label.

    How your assistant reads

    reef loads an index first, then engrams. This is the LLM Wiki pattern, adapted for shared, permissioned memory, and it is why a large memory stays cheap to consult.

    1. The assistant calls load_index and gets a map of every engram it may see: path, title, tags, and the one-line description. No engram bodies.
    2. It reads the map, decides what this conversation needs, and asks recall, which returns the passages that best answer the question.
    3. When passages are not enough, it reads whole engrams with open. For advice or preparation, brief gathers everything that bears on a topic.

    The index is rebuilt from the database on every call, so it cannot fall out of date. Search runs under the same row-level security as every other read, so it can never surface an engram its caller could not open.

    How your assistant writes

    Nothing is recorded silently. Mid-conversation, a fact worth keeping goes through remember, which stages it as a dated line in that space's inbox. Before the conversation ends, the assistant says what it is keeping, so you can strike anything first.

    An inbox entry is not memory yet. A tidy-up — ask for one any time — compiles inboxes onto real engrams, flags engrams that have gone stale, and surfaces contradictions between your engrams and shared ones instead of quietly picking a winner.

    Deliberate capture, reviewed by you, is the design: reef will not transcribe your conversations behind your back.

    For edits to real engrams rather than the inbox, an assistant uses:

    ToolWhat it does
    logAdds one entry to the end of a journal, training log or meeting notes. Nothing else changes.
    writeCreates or replaces whole engrams, up to 20 at once, all or nothing.
    correctReplaces one exact passage, leaving the rest of the engram untouched.
    undoRestores an earlier version of an engram.

    Connect an assistant

    Every route below signs in through the same browser flow. Use the email address you were invited on — that is how invitations to a space reach you, and signing in with a different one gets you a different, empty account.

    Claude

    1. Go to Settings → Connectors and choose to add a custom connector.
    2. Paste https://reefwith.me/mcp as the address.
    3. Claude opens a sign-in page. Sign in once.

    After this, every conversation — desktop, web, or the phone app — starts already knowing.

    ChatGPT

    1. In the desktop app, go to Settings → MCP servers and select Add server.
    2. Name it reef, choose Streamable HTTP, paste https://reefwith.me/mcp, and save. Then select Restart.
    3. Back in MCP servers, select Authenticate and sign in.

    The ChatGPT desktop app and Codex share this setup on the same computer, so doing it here does it for both.

    Codex

    codex mcp add reef --url https://reefwith.me/mcp
codex mcp login reef

    The second command finishes the sign-in in your browser.

    Claude Code

    The plugin carries the connector and three commands with it:

    claude plugin marketplace add diepzee/reef
claude plugin install reef@haai

    /reef:recall answers from memory rather than from guesswork, /reef:remember files something away, and /reef:whats-new reports what the other people's assistants have been writing.

    The CLI

    Two packages, both installing a reef command:

    InstallWhat you get
    Pythonuv tool install reef-cliEvery tool as a named command
    npmnpm install -g @haai/reef-clilogin, tools, and call

    Named commands use hyphens, so load_index becomes load-index. Every result is JSON, and an error such as not_found also exits non-zero. 

    reef login
reef load-index
reef recall "when is the boiler serviced?"
reef open personal/profile.md personal/preferences.md
reef log personal climbing-log.md --heading "2026-11-19" --entry "Sent the blue route."
reef call open '{"refs":["personal/plans.md"]}'

    reef call takes any tool name and a JSON object, so it reaches everything the named commands do. Run reef tools for the live schemas, and reef <command> --help for arguments.

    Set REEF_MCP_URL to point at another server, or REEF_ACCESS_TOKEN for a headless run. Each package caches its own token, so signing in with one does not sign in the other.

    There is also a bundled agent skill at skills/reef, which teaches an assistant the retrieval protocol, private-by-default writing, optimistic locking, and when it must ask you before acting.

    Your assistant's own memory

    Claude and ChatGPT each keep a memory of their own, and it loads before your assistant has done anything — including before it reads reef. So the two can disagree: a job you left, a name that changed, a preference you have since dropped.

    Your assistant is told to treat reef as the record. When what it remembers on its own contradicts an engram, it should tell you both versions rather than quietly choosing, and write down whichever one you confirm.

    If you would rather have one memory instead of two, turn the built-in one off. In ChatGPT that is Settings → Personalization → Memory, where you switch off both Reference saved memories and Reference chat history. In Claude it is Settings → Memory. Nothing in reef changes: your engrams stay where they are, and every assistant you connect reads the same ones.

    Tool reference

    These are the sixteen tools an assistant sees over MCP, and the commands the CLI mirrors. Every tool but search and fetch takes a reason: a few words from your request, which reef logs privately for you, to improve reef.

    Reading

    ToolWhat it does
    load_indexWhere a conversation starts: the rules an assistant follows, your persona, and the map of every engram and file you may see. No bodies.
    recallAnswers a question with the passages that fit best, and where each comes from. That includes the text inside your files, with the page.
    briefGathers what bears on a topic, to advise or prepare you.
    openReads whole engrams, optionally as they stood at a past date, and the text of stored files, from any page.
    catch_upWhat has changed in your spaces, and who changed it.

    Writing

    ToolWhat it does
    rememberStages a fact as a dated line in the space's inbox.
    logAdds one entry to the end of a log.
    writeCreates or replaces whole engrams.
    correctReplaces one exact passage of an engram.
    undoRestores an earlier version of an engram.
    store_fileKeeps a document or an image, with a description to find it by. Reef then reads the text inside it.

    Changes that need your yes

    ToolWhat it does
    shareMoves a personal engram, or one section of it, into a shared space.
    forgetDeletes an engram and its history, or a stored file, for good.
    instructReplaces your persona, which every assistant of yours follows.

    Each of these takes two calls. The first changes nothing and shows the effect. The second happens only after you say yes.

    For connectors

    ToolWhat it does
    searchFinds engrams and files by words, for connectors that can call only two tools.
    fetchRetrieves one result of search.

    Creating, renaming and deleting spaces, and inviting and removing members, are done on the reef website, by you. An assistant cannot do them.

    Sharing and invitations

    Sharing is deliberate and permanent. Moving something out of your private space takes two steps. First your assistant calls share, which shows you the exact text and names everyone who will be able to read it. Only after your yes does it call share again, and the text moves.

    Writing private content into a shared space any other way is refused — not discouraged, refused. And there is no un-sharing: once other people can read something, treat it as read.

    reef sends no email. Inviting someone records that they may join — it does not tell them. Pass the invitation on yourself, however you normally reach that person, or they will never know.

    You invite people on the reef website, to a space or to reef itself. An invitation is addressed to an email, and that address is the one they must sign in with.

    Your data

    Engrams are Markdown from the moment you write them. The browser app exports two ways:

    • Current content, as a Markdown archive or JSON.
    • Everything, as one download with full revision history and your stored file bytes.

    Both are plain files that outlive this deployment. Export is one-way, out of reef — nothing here locks your memory in. Deleting means deleted.

    Privacy is enforced by the database, not by application code. Every engram, file and membership is guarded by PostgreSQL row-level security, so a query with a forgotten filter returns nothing rather than somebody else's data. Getting it wrong fails closed.

    The privacy page spells out what is stored, where it lives, who can see it, and how to get it back or delete it. The terms cover the agreement itself.

    Troubleshooting

    My assistant answers without checking memory

    Ask it to load the index. Connecting reef makes the memory available; it does not force an assistant to consult it every turn. In Claude Code, /reef:recall asks for an answer from memory rather than from guesswork.

    I invited someone and they heard nothing

    That is expected. reef sends no email, so the invitation reaches nobody until you pass it on yourself.

    I signed in and my spaces are gone

    You are probably in a second account. Invitations are addressed to an email address, so signing in with a different one gives you a new, empty reef rather than an error. Sign out and sign back in with the address you were invited on.

    The CLI is signed in but my assistant is not

    Each package caches its own token, and the MCP connection has its own again. Signing in to one does not sign in the others — do each once.

    Someone mentioned a space I cannot find

    Space names are per person. Their name for a space is not necessarily yours, so ask what is on the engrams rather than what the space is called — or check load_index for what you actually have. If it is nowhere, you have not been invited to it yet.
